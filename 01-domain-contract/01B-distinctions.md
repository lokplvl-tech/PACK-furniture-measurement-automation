# Ключевые различения: Автоматизация замера в параметрическую модель мебели

> Источник: FPF A.7 (Strict Distinction)

### FMA.D.001: Скрипт Базиса как параметрическая функция ≠ готовая модель

**Определение A (параметрическая функция):** скрипт (`Example/Моя первая тумбочка 2.js`, проверено 01.08.2026) - не файл модели, а ПРОГРАММА, которая строит модель заново каждый раз из чисел-параметров (ширина, глубина, высота, материалы, тип фрезеровки) - изменил число, модель перестроилась целиком.

**Определение B (готовая модель):** статичный файл с уже построенной геометрией, без возможности пересчитать по новым параметрам без ручной правки.

**Тест:** «Если поменять одно число на входе, модель перестроится сама, или её нужно перерисовывать руками?»

**Почему важно для этого Пака:** вся идея моста «замер → модель» работает, только если Базис принимает именно параметрическую функцию (определение A) - тогда данные замера подставляются как параметры, и модель Базиса генерируется автоматически. Если бы Базис работал только с готовыми моделями (определение B), автоматизация была бы невозможна без переписывания геометрии вручную под каждый новый замер.

**Подтверждение по первоисточнику:** реальный пример именно так и устроен - функция `Make()` полностью перестраивает геометрию из значений `Dl` (длина), `Gl` (глубина), `H` (высота) и других параметров, объявленных в `MakeProperties()`.

**SoTA:** `current`, подтверждено на реальном рабочем примере, не по документации в отрыве от практики.
