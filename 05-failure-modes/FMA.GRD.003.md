## [FMA.GRD.003] Пятый параметр AddFrontPanel - положение по глубине, не толщина панели

### Definition

`AddFrontPanel(x1, y1, x2, y2, z)` - пятый параметр `z` задаёт **координату положения панели по глубине** (где именно вдоль оси глубины стоит тонкий лист), а не толщину самого листа. Фактическая толщина построенной панели определяется толщиной **активного материала** на момент вызова (`<Материал>.SetActive()` непосредственно перед `AddFrontPanel`, толщина читается как `ActiveMaterial.Thickness`). Ошибочное предположение «раз это фронтальная панель типа фасада, пятый параметр - это её толщина в мм» приводит к тому, что реальная толщина фасада никак не связана со значением, которое разработчик скрипта пытался туда передать.

### Category

**This failure mode is**: `knowledge-gap` - неверная модель API, не ошибка синтаксиса или логики порядка.

### Observable Symptoms

- [ ] В скрипте передаётся переменная вроде `FasadThick.Value` (или число «19», «16») пятым параметром `AddFrontPanel`, ожидая, что панель станет такой толщины
- [ ] Реальная толщина фасада в 3D не совпадает с ожидаемым числом - управляется только выбором материала в окне параметров
- [ ] Попытка «гарантировать минимум 19мм» через этот параметр не работает - вместо этого нужно проверять `ActiveMaterial.Thickness` после `.SetActive()`

### Root Causes

| Cause | Description |
|-------|-------------|
| Естественная (но неверная) аналогия с другими Add*Panel | В `AddHorizPanel(x1, z1, x2, z2, y)` последний параметр действительно определяет положение по высоте - легко перенести ту же интуицию на `AddFrontPanel`, не сверив с реальным примером |
| Реальный боевой пример использует этот параметр только с уже понятным смыслом («глубина», `Gl.Value`) - смысл «z = положение», не «z = толщина» - неявный, требует внимательного чтения, не следует из названия параметра |

### Consequences

- Требование «толщина фасада минимум 19мм» реализуется неверно - формально код «что-то делает» с числом 19, но панель фактически всё равно берёт толщину из материала (например, 16мм у ДСП бук), требование молча не выполняется
- Задача решается верно только после явной проверки `ActiveMaterial.Thickness` и предупреждения пользователю, если материал тоньше нужного

### Guard (блокирующий инвариант)

Толщина фронтальной панели проверяется ТОЛЬКО через `ActiveMaterial.Thickness` сразу после `<Материал>.SetActive()`, никогда не передаётся отдельным числовым параметром в `AddFrontPanel`. Если нужен минимум толщины - явная проверка с предупреждением (`alert`), не попытка задать геометрией.

### Detection Methods

| Detection Method | When to Apply |
|--------------------|----------------|
| Сверка любого числа, передаваемого в `AddFrontPanel` пятым параметром, с реальными примерами использования (`Gl.Value`, «10», `Gl.Value - 20 - Thick`) - все они про положение, не про толщину | При написании нового вызова `AddFrontPanel` |
| Визуальная проверка реальной толщины построенной панели в 3D относительно ожидания | После реального прогона в Базисе |
