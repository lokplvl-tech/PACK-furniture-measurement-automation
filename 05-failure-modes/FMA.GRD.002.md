## [FMA.GRD.002] Перепутан порядок y1/y2 (низ/верх) в AddFrontPanel - не ошибка, а перекос

### Definition

`AddFrontPanel(x1, y1, x2, y2, z)` ожидает `y1 < y2` (нижняя граница панели меньше верхней, по возрастанию - тот же порядок, что и `x1 < x2`). Если передать `y1` больше `y2` (например, `y1 = H.Value`, `y2 = 0`), Базис **не бросает исключение** - молча строит панель со скошенной/некорректной геометрией, которая на глаз выглядит как перекошенный параллелограмм, а не прямоугольник.

### Category

**This failure mode is**: `script-failure` - самый опасный подвид: **не даёт сообщения об ошибке**, обнаруживается только визуально при реальном прогоне.

### Observable Symptoms

- [ ] Скрипт выполняется без ошибок в строке статуса
- [ ] Построенная деталь визуально перекошена (не прямоугольник, а параллелограмм/скошенная лента)
- [ ] Особенно заметно при совмещении с соседними панелями, построенными корректно (крышка/боковины ровные, только один элемент кривой)

### Root Causes

| Cause | Description |
|-------|-------------|
| Скопирован фрагмент кода без сверки порядка аргументов с реальным примером | Реальный пример («Моя первая тумбочка 2.js») везде строго возрастающий порядок (`Hd.Value + 2, ..., H.Value - 2`) - расхождение осталось незамеченным при написании |
| Функция не валидирует входные аргументы | Базис доверяет вызывающему коду, не проверяет `y1 < y2` перед построением |

### Consequences

- Ложное впечатление, что скрипт «не работает» или «строит одну деталь вместо пяти» - на деле все детали строятся, но одна (или несколько) визуально неотличимо сливаются с остальными из-за перекоса
- Трата времени на неверную диагностику (проверка камеры/зума вместо кода)

### Guard (блокирующий инвариант)

Перед каждым вызовом `AddFrontPanel`/`AddHorizPanel`/`AddVertPanel` - явно сверять порядок координат с реальным рабочим примером (`Example/Моя первая тумбочка 2.js`), не с логикой «как удобнее написать». Все границы - по возрастанию.

### Detection Methods

| Detection Method | When to Apply |
|--------------------|----------------|
| Визуальная проверка формы каждой построенной панели в 3D после реального прогона в Базисе | После каждого изменения геометрии, до передачи клиенту |
| Сверка аргументов новой строки `AddFrontPanel` с эталонной строкой из боевого примера построчно | При написании/правке скрипта, до первого прогона |

### Notes

Найдено на реальном прогоне 06.08.2026 - корпус кухонного модуля строился коробкой правильно (крышка/боковины/дно), но фасад (единственная панель с перепутанным порядком) выглядел скошенной лентой поверх ровной коробки.
