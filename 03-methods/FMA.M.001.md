## [FMA.M.001] Устройство BAZIS-Script (по реальному примеру)

### Definition

Скриптовый API Базис-Мебельщика - параметрическое построение корпусной мебели программой на JavaScript-подобном синтаксисе (реальный пример использует именно `function`/`var`/фигурные скобки - расходится с кратким описанием на официальном сайте, которое называет язык «Pascal-подобным»; в этом Пake источником истины считается реальный рабочий пример, не общее описание сайта - см. честная оговорка ниже).

### Источник

`C:\Users\Фёдор\Documents\Базис\Example\Моя первая тумбочка 2.js` (реальный рабочий пример, не учебная выжимка) + `https://cdn.bazissoft.ru/documentation/ru/BAZIS-Script_functions.html` (официальная документация - проверено 01.08.2026).

### ✅ Расхождение источников - разрешено (01.08.2026)

Официальный сайт (по краткому автоматическому чтению страницы) когда-то описывал язык скриптов как «Pascal-подобный». Реальный пример на диске пилота написан в синтаксисе JavaScript. Прямая сверка с полным PDF-руководством `BazisQuick_start.pdf` (326 страниц, версия БАЗИС 2025.7.2, прочитано построчно 01.08.2026) закрывает вопрос однозначно в пользу JavaScript:

- Раздел 3.13 «Настройка параметров скриптов» (с. 65) - модуль запускает скрипты на движке **Node.js** (выбор между `Node v8` и `Node v20`) - Node.js исполняет только JavaScript, Pascal для него не существует как понятие.
- Таблица путей к файлам модуля (с. 49) - тип файлов прямо назван «Файлы скриптов (`*.js`)».
- Раздел 3.13.2 «Настройка быстрого запуска скриптов» - список скриптов берётся из той же папки, что и меню `Скрипты` в главном меню модуля, тем же списком `*.js`-файлов.

Три независимых места одного и того же официального документа сходятся на JavaScript - расхождение с ранним «Pascal-подобным» описанием сайта объясняется либо устаревшей формулировкой сайта, либо неточностью автоматического чтения страницы в прошлой сессии. Источником истины для этого Пака остаётся JavaScript, подтверждено дважды (реальный пример + полное официальное руководство).

### Структура типового скрипта (по реальному примеру)

1. **Загрузка/сохранение настроек** - `Action.Properties.Load/Save(ФайлНастроек)` - параметры между запусками не теряются.
2. **Описание диалога параметров** (`MakeProperties()`) - создаются поля ввода: числа (`Prop.NewNumber`), группы (`Prop.NewGroup`), выбор материала (`.NewMaterial`), выбор фурнитуры (`.NewFurniture`), выпадающий список (`.NewCombo`), выбор файла фрезы (`.NewSelector`).
3. **Проверка вводимых значений на лету** - `Prop.OnChange`, можно показать предупреждение (`alert(...)`), если введены нелогичные значения (в примере - высота фасада больше высоты цоколя).
4. **Построение геометрии** (`Make()`) - вызывается заново при каждом изменении параметра:
   - `AddHorizPanel`/`AddVertPanel`/`AddFrontPanel(X, Y, X2, Y2, Z)` - панели корпуса по координатам.
   - `.AddCut(Имя)` + `Trajectory.AddLine/AddArc3` + `Contour` - вырезы и пазы по траектории.
   - `.AddButt(Кромка, СторонаПанели)` - кромкование сторон панели.
   - `AddSymmetry(Панель, Точка, Ось)` - зеркальное построение (например, правый бок из левого).
   - `BeginBlock/EndBlock` - группировка связанных элементов (например, вся дверь как один узел с анимацией открывания).
5. **Подключение фурнитуры** - `OpenFurniture('Файл.f3d')` + `.Mount(НаКакойПанели, ОтноситьноЧего, X, Y, Z)` - точное позиционирование готовых компонентов (петли, полкодержатели, эксцентрики, шканты) относительно уже построенных панелей.

### Практический смысл для этого Пака

Если данные замера (метод трёх точек) дают реальные размеры и отклонения помещения, эти числа МОГУТ напрямую стать значениями `Dl.Value`, `Gl.Value`, `H.Value` и подобных полей в таком скрипте - то есть теоретически возможно сгенерировать (или заполнить шаблон) такого скрипта программно, не вручную, если есть программа-посредник (кандидат - Перфолента, см. рабочий продукт 36) между источником данных замера и файлом скрипта, который потом открывается в самом Базисе.
